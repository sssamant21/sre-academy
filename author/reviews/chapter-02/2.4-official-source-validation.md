## Validation Summary

No blocking factual issue was found in the Chapter 2.4 author draft.

The draft is aligned with official Kubernetes documentation on these points:

- Kubernetes components coordinate primarily through the API server.
- The API server exposes the Kubernetes HTTP API and uses etcd for API server data.
- Controllers watch cluster state and move actual state toward desired state.
- Built-in controllers commonly make changes by writing to the API server.
- Kubernetes clients can list current state and then watch changes from a `resourceVersion`.
- Watch clients must handle history expiration and `410 Gone` by relisting.
- The scheduler watches for Pods without assigned nodes, filters and scores feasible nodes, and binds Pods.
- kubelet observes assigned Pods and reports status back to the API server.
