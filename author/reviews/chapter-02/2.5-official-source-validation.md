## Validation Summary

No blocking factual issue was found in the Chapter 2.5 author draft.

The draft is aligned with official Kubernetes documentation on these points:

- Nodes can be added through kubelet self-registration or manual Node object creation.
- Node status includes addresses, conditions, capacity, allocatable resources, and system information.
- `Ready=True`, `Ready=False`, and `Ready=Unknown` have different operational meanings.
- Node heartbeats use Node status updates and Lease objects in the `kube-node-lease` namespace.
- The node controller monitors node health and updates the Ready condition when nodes become unreachable.
- The node controller can trigger API-initiated eviction for Pods on unreachable nodes after a delay.
- Kubernetes adds taints for node conditions such as not-ready, unreachable, memory pressure, disk pressure, PID pressure, and network unavailable.
- Node-pressure eviction is kubelet-driven and is not the same as API-initiated eviction.
- Node-pressure eviction does not respect PodDisruptionBudgets.
- `kubectl drain` uses safe evictions where possible and respects PodDisruptionBudgets.
