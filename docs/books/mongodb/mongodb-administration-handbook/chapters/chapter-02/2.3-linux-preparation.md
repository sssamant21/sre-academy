### Canonical technical baseline

- Validate the selected MongoDB release against the current supported operating-system and kernel matrix before installation or upgrade.
- Use supported Linux filesystems; XFS is strongly recommended for WiredTiger data-bearing deployments.
- Validate storage latency, throughput, mount configuration, capacity, and readahead before production acceptance.
- Size file-descriptor and process limits for production connection and workload requirements; MongoDB warns when the open-files limit is below 64,000.
- Treat WiredTiger cache and Linux filesystem cache as complementary consumers of memory and avoid arbitrary cache enlargement without repeatable workload evidence.
- Configure swap/swappiness according to the MongoDB version, deployment topology, workload, and host-sharing model rather than applying a universal disable-swap rule.
- For MongoDB 8.0 and later, follow current MongoDB THP guidance; for MongoDB 7.0 and earlier, follow the version-specific THP-disable guidance.
- Treat NUMA explicitly on NUMA hosts and validate MongoDB-aware memory placement and zone-reclaim behavior.
- Configure host security controls such as SELinux/AppArmor and firewalls rather than broadly disabling them.
- Establish DNS, time synchronization, package provenance, logging, metrics, disk/CPU/memory observability, and reboot validation before accepting a node into production.
- Revalidate current MongoDB production notes during every installation and upgrade because kernel and platform compatibility guidance can change between releases.
