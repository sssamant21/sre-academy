# 5.10 -- Serializable Isolation and SSI

**Status:** Complete -- Revised Final / Canonical Edition

PostgreSQL Serializable isolation uses Serializable Snapshot Isolation (SSI) to detect dangerous dependency structures and abort transactions when needed so committed results are consistent with some serial execution order.

Serializable does not mean all transactions execute one at a time. Predicate-lock information supports SSI conflict detection and should not be confused with ordinary blocking locks.

## Application Contract
Transactions must be prepared to receive serialization failures and retry the complete business transaction with bounded backoff and idempotency safeguards.

`SERIALIZABLE READ ONLY DEFERRABLE` can be useful for long read-only work because PostgreSQL can wait for a snapshot that avoids later serialization failure from SSI conflicts.

## Rules
1. Serialization failure is an expected correctness mechanism, not database corruption.
2. Retry the whole transaction.
3. Bound retries and instrument them.
4. Keep serializable transactions short where possible.
5. Load-test conflict-heavy workloads before production rollout.
