# 5.11 -- Read-Only and Deferrable Transactions

**Status:** Complete -- Revised Final / Canonical Edition

Read-only transactions restrict database-writing operations but can still consume connections, snapshots, memory, CPU, I/O, and visibility horizons. `DEFERRABLE` is meaningful with Serializable read-only transactions and allows PostgreSQL to wait for a safe snapshot.

```sql
BEGIN TRANSACTION ISOLATION LEVEL SERIALIZABLE READ ONLY DEFERRABLE;
-- consistent reporting workload
COMMIT;
```

## Production Guidance
Use bounded statement/transaction timeouts for analytical services as appropriate. Route eligible analytics to replicas only after validating freshness and isolation requirements. A read-only transaction can still harm vacuum progress if its snapshot is held for a long time.

## Rules
1. Read-only does not mean resource-free.
2. Monitor age of analytical transactions.
3. Use deferrable mode only where waiting for a safe snapshot is acceptable.
4. Validate standby semantics before offloading.
5. Protect OLTP SLOs from unbounded analytical snapshots.
