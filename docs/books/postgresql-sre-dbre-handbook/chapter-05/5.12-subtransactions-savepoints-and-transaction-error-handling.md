# 5.12 -- Subtransactions, SAVEPOINTs, and Transaction Error Handling

**Status:** Complete -- Revised Final / Canonical Edition

Savepoints allow partial rollback inside a transaction. PostgreSQL implements nested transactional behavior through subtransactions rather than true independently committed nested transactions.

```sql
BEGIN;
SAVEPOINT s1;
-- operation
ROLLBACK TO SAVEPOINT s1;
-- continue safely
COMMIT;
```

## Production Risks
Deep or high-volume subtransaction use can increase overhead and complicate troubleshooting. Application frameworks that automatically create savepoints should be load-tested under failure-heavy workloads.

## Rules
1. A savepoint does not create an independently durable nested transaction.
2. Roll back failed work before continuing.
3. Keep savepoint depth bounded.
4. Instrument transaction-abort and retry paths.
5. Prefer clear business transaction boundaries over excessive nested recovery logic.
