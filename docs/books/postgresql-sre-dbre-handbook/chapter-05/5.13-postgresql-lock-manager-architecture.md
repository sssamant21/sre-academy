# 5.13 -- PostgreSQL Lock Manager Architecture

**Status:** Complete -- Revised Final / Canonical Edition

PostgreSQL combines MVCC with explicit lock management. Heavyweight locks protect relations and other lockable objects; transaction and virtual-transaction locks participate in waits; row locks are primarily represented in tuple state; predicate locks support Serializable SSI; advisory locks are application-defined.

`pg_locks` exposes outstanding locks in the lock manager and should be correlated with `pg_stat_activity` and `pg_blocking_pids()`.

## Production Guidance
Blocking is not automatically a defect. Diagnose blocker, blocked workload, lock mode, object, transaction age, query, and business owner before intervention.

## Rules
1. Understand lock type before remediation.
2. Blocking chains matter more than isolated waiting sessions.
3. Root blockers are the primary incident target.
4. Termination can trigger rollback and additional I/O.
5. Capture evidence before killing sessions when time permits.
