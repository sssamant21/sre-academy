# 5.14 -- Table-Level Locks and Lock Modes

**Status:** Complete -- Revised Final / Canonical Edition

PostgreSQL provides multiple table-level lock modes with defined conflict relationships. Ordinary queries, DML, maintenance, and DDL acquire different modes depending on operation.

## Production Guidance
Before a schema or maintenance change, determine the required lock mode, likely blockers, expected acquisition time, transaction duration, queueing risk, and backout plan. A waiting strong lock can become an application-latency risk.

## Monitoring
Correlate `pg_locks`, `pg_stat_activity`, wait events, and `pg_blocking_pids()`. Use bounded lock-wait policies for automated change tooling where indefinite waiting is unacceptable.

## Rules
1. Know the lock mode before production changes.
2. Keep DDL transactions short.
3. Preflight blockers for high-impact operations.
4. Treat lock queues as an SLO risk.
5. Test operational impact in representative environments.
