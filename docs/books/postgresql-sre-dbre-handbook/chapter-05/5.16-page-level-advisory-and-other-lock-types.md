# 5.16 -- Page-Level, Advisory, and Other Lock Types

**Status:** Complete -- Revised Final / Canonical Edition

PostgreSQL uses additional lock mechanisms beyond table and row locking. Page-level locks are internal and normally short-lived. Advisory locks expose application-controlled locking using integer keys and can be session- or transaction-scoped. Predicate locks support Serializable SSI and have different semantics from blocking heavyweight locks.

## Advisory Lock Safety
Advisory locks are cooperative: PostgreSQL does not know the business resource represented by a key. Establish a documented key namespace, ownership model, scope, timeout, and release strategy. Session-level advisory locks can outlive transaction rollback and therefore deserve special care with connection pools.

## Rules
1. Do not use advisory locks without a key convention.
2. Prefer transaction-scoped advisory locks when lifecycle should follow the transaction.
3. Monitor pooled connections for leaked session locks.
4. Do not confuse predicate locks with ordinary blocking locks.
5. Keep custom locking designs simple and documented.
