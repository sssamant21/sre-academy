# 5.17 -- Explicit Locking and SELECT FOR UPDATE/SHARE

**Status:** Complete -- Revised Final / Canonical Edition

PostgreSQL provides explicit row-locking clauses including `FOR UPDATE`, `FOR NO KEY UPDATE`, `FOR SHARE`, and `FOR KEY SHARE`, plus table `LOCK` commands. Use them when application correctness requires coordination beyond ordinary MVCC visibility.

```sql
BEGIN;
SELECT * FROM jobs
WHERE id = $1
FOR UPDATE;
-- validate and modify protected state
COMMIT;
```

## Production Guidance
Lock only what is necessary and acquire locks in a consistent order. Do not hold locks while calling remote services. Evaluate `NOWAIT` for fail-fast behavior and `SKIP LOCKED` for suitable queue consumers.

## Rules
1. Explicit locks must protect a documented invariant.
2. Lock order is part of application design.
3. Keep lock scope and duration minimal.
4. Do not add locks merely to hide an isolation bug.
5. Load-test contention and retry behavior.
