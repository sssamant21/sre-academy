# 5.18 -- Lock Queues, Wait Events, and Blocking Chains

**Status:** Complete -- Revised Final / Canonical Edition

Lock incidents are graph problems: one root blocker can create a large queue of blocked sessions. Diagnose the chain rather than killing random waiters.

```sql
SELECT pid, pg_blocking_pids(pid) AS blockers,
       wait_event_type, wait_event, state, xact_start, query
FROM pg_stat_activity
WHERE cardinality(pg_blocking_pids(pid)) > 0;
```

## Incident Method
1. Capture blocked and blocking PIDs.
2. Identify root blocker and transaction age.
3. Identify lock/object and business owner.
4. Assess rollback cost and SLO impact.
5. Cancel or terminate only under approved criteria.
6. Confirm queue drain and application recovery.
7. Preserve evidence for RCA.

## Rules
1. Root blocker first.
2. Wait count alone is insufficient; measure wait duration and SLO impact.
3. `pg_locks` plus `pg_stat_activity` is the core diagnostic pair.
4. Termination can cause expensive rollback.
5. Alert on sustained blocking, not harmless micro-waits.
