# 5.21 -- Transaction ID Wraparound and Freeze Management

**Status:** Complete -- Revised Final / Canonical Edition

Normal PostgreSQL transaction IDs are 32-bit and require wraparound-aware maintenance. VACUUM freezing marks sufficiently old committed tuple versions so visibility remains safe as XIDs advance. PostgreSQL also protects against MultiXact wraparound used in multi-transaction row-locking state.

## Monitoring
```sql
SELECT datname, age(datfrozenxid) AS xid_age
FROM pg_database
ORDER BY age(datfrozenxid) DESC;
```
Also monitor relation freeze age, MultiXact age, autovacuum activity, prepared transactions, long transactions, and storage/I/O capacity needed for anti-wraparound work.

## Emergency Principles
When approaching wraparound protection limits, remove blockers such as obsolete prepared/open transactions where safe, ensure vacuum can run, protect I/O capacity, and follow supported PostgreSQL procedures. Do not disable anti-wraparound safeguards or restart merely to avoid vacuum.

## Rules
1. Wraparound is a data-availability/data-safety risk.
2. Anti-wraparound vacuum has priority over routine performance convenience.
3. Monitor XID and MultiXact age continuously.
4. Investigate old prepared transactions and backend horizons.
5. Maintain capacity for emergency vacuum work.
