# 5.23 -- Transaction and Lock Monitoring, Metrics, and Alerting

**Status:** Complete -- Revised Final / Canonical Edition

A production concurrency dashboard should combine activity, locks, waits, deadlocks, transaction age, XID age, query latency, and application SLOs.

## Core Telemetry
- `pg_stat_activity`: state, transaction/query age, wait events, backend XID/xmin;
- `pg_locks`: held/requested locks;
- `pg_blocking_pids()`: blocking relationships;
- `pg_stat_database`: deadlock and transaction counters;
- database/relation freeze age;
- logs: deadlocks, lock waits, statement errors;
- application retry/timeout metrics.

## Alerting
Alert on sustained blocking duration, old transactions, repeated deadlocks, growing serialization-failure rate, dangerous XID/MultiXact age, and SLO degradation. Avoid paging on every short lock wait.

## Rules
1. Alerts must be actionable.
2. Baseline by workload.
3. Preserve application identity via `application_name`.
4. Correlate database and service telemetry.
5. Track trends and rates, not isolated counters.
