# 5.5 -- Transaction IDs, XIDs, and Transaction Visibility

**Status:** Complete -- Revised Final / Canonical Edition

PostgreSQL uses transaction identifiers as part of MVCC visibility. Normal XIDs are finite 32-bit identifiers and are compared using wraparound-aware semantics. Not every transaction immediately needs a permanent XID; read-only work can operate with virtual transaction identity until an XID is required.

## Operational Importance
XID age is a safety dimension. Vacuum freezing ensures sufficiently old committed tuple versions remain safely visible without depending indefinitely on aging normal XIDs.

Useful checks include database `datfrozenxid` age and table `relfrozenxid` age. Prepared transactions and long-running sessions can retain old transaction horizons and must be included in wraparound investigation.

## Rules
1. Never reason about XIDs as monotonically increasing unlimited integers.
2. Monitor database and relation XID age.
3. Treat wraparound protection as a data-safety mechanism.
4. Investigate old prepared and open transactions during age incidents.
5. Never disable anti-wraparound vacuum as a performance workaround.
