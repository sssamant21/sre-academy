# 5.6 -- Snapshots and MVCC Visibility Rules

**Status:** Complete -- Revised Final / Canonical Edition

A PostgreSQL snapshot defines which transaction effects are visible to a statement or transaction under its isolation semantics. Visibility is determined from tuple transaction metadata plus snapshot state; it is not simply based on wall-clock time.

Read Committed normally takes a fresh command snapshot for each command. Repeatable Read and Serializable operate with a stable transaction view subject to their additional semantics.

## Production Risks
Long-lived snapshots can retain old row versions and increase vacuum/storage pressure. Exported snapshots and replication-related horizons require deliberate lifecycle management.

## Rules
1. Snapshot lifetime is a capacity and concurrency concern.
2. Do not equate commit timestamp with MVCC visibility logic.
3. Monitor old transactions when dead tuples persist.
4. Understand isolation semantics before debugging apparently stale reads.
5. Keep analytical transactions bounded on high-churn primaries.
