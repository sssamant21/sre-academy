# 5.8 -- Read Committed Isolation

**Status:** Complete -- Revised Final / Canonical Edition

Read Committed is PostgreSQL's default isolation level. Each command sees a snapshot as of the beginning of that command, so successive commands in one transaction can observe different committed database states.

UPDATE/DELETE/locking commands can wait for concurrent row changes and then re-evaluate affected rows according to Read Committed rules.

## Production Guidance
Do not assume two SELECTs in one Read Committed transaction see identical data. Protect multi-step business invariants with constraints, explicit row locking, higher isolation, or application design as appropriate.

## Failure Pattern
`SELECT balance` followed later by an UPDATE based on that value can race with another transaction if the invariant is not protected.

## Rules
1. Default does not mean correct for every workflow.
2. Statement snapshots can differ within one transaction.
3. Test read-modify-write races.
4. Use locks/constraints when business state must not change between steps.
5. Keep lock-holding transactions short.
