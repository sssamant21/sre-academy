# 5.9 -- Repeatable Read Isolation

**Status:** Complete -- Revised Final / Canonical Edition

PostgreSQL Repeatable Read provides a stable transaction snapshot and prevents the transaction from observing changes committed after that snapshot in ordinary reads. PostgreSQL's implementation is stronger than the minimum SQL requirement in important respects, but applications must still handle update conflicts and should not assume Serializable guarantees.

## Production Guidance
Use for workflows needing a stable database view, such as consistent multi-query analysis, while keeping transaction duration bounded. Updates against rows changed since the transaction snapshot can result in transaction aborts requiring retry.

## Rules
1. Stable snapshot can increase old-version retention if held too long.
2. Repeatable Read is not equivalent to Serializable.
3. Design whole-transaction retries.
4. Avoid long interactive sessions at this level.
5. Monitor transaction age on high-churn systems.
