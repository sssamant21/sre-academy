# 6.10 -- Sequential, Index, Index-Only, and Bitmap Scan Strategies

**Status:** Complete -- Revised Final / Canonical Edition

PostgreSQL chooses among sequential, index, index-only, bitmap, and parallel-capable scans according to estimated cost. Sequential scans are often correct for large fractions of a table. Index scans excel when selective access and ordering benefits outweigh random access. Bitmap scans can combine index matches efficiently for medium selectivity. Index-only scans require suitable indexes and benefit when visibility information allows heap visits to be avoided.

Tune by matching access paths to actual predicates and data distribution. Avoid creating duplicate/low-value indexes solely because a sequential scan appeared in one plan. Measure write amplification, storage, cache footprint, maintenance, and query benefit before adding indexes.
