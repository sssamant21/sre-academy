# 6.12 -- Sorting, Aggregation, DISTINCT, and GROUP BY Execution

**Status:** Complete -- Revised Final / Canonical Edition

Sorting and aggregation can be CPU-, memory-, and temporary-I/O-intensive. PostgreSQL can use sort-based and hash-based strategies depending on semantics and estimated costs. `ORDER BY`, `DISTINCT`, window operations, grouping, and merge joins may introduce ordering work.

Inspect plan sort methods, memory usage, disk spill, hash batches, estimated groups, input rows, and concurrency. `work_mem` applies to individual operations and can be consumed multiple times per query and across concurrent sessions; it is not a per-session memory ceiling.

Prefer query/index/statistics improvements and workload-specific memory changes over indiscriminate global `work_mem` increases.
