# 6.13 -- CTEs, Subqueries, Views, and Query Transformation

**Status:** Complete -- Revised Final / Canonical Edition

CTEs, subqueries, and views are semantic SQL constructs whose optimization behavior depends on PostgreSQL version and query characteristics. Do not rely on outdated assumptions that every CTE is always an optimization fence.

Use `EXPLAIN` to verify whether predicates are pushed down, expressions are duplicated, intermediate results are materialized, or repeated work occurs. `MATERIALIZED` and `NOT MATERIALIZED` are semantic/performance tools that require testing.

Refactoring for performance must preserve correctness, security-barrier behavior where relevant, volatility semantics, row multiplicity, and transaction behavior.
