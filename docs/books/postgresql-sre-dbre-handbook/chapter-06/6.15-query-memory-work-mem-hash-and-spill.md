# 6.15 -- Query Memory: work_mem, Hash Memory, and Temporary Spill

**Status:** Complete -- Revised Final / Canonical Edition

`work_mem` limits memory available to individual sort/hash-style operations before external processing may occur; a query can have multiple such operations, and many sessions can execute concurrently. Hash operations also interact with `hash_mem_multiplier`.

Capacity model:
```text
possible query memory ~= concurrent operations x per-operation allowance x active concurrency
```
This is an approximation, not a PostgreSQL reservation formula.

Monitor temporary bytes/files, plan spill details, memory pressure, OOM/eviction risk, storage latency, and concurrency. Tune expensive workloads at role/session/query scope when possible. Global memory increases require host/container headroom analysis and rollback.
