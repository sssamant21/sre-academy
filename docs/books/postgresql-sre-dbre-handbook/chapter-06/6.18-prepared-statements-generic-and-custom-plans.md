# 6.18 -- Prepared Statements, Generic Plans, and Custom Plans

**Status:** Complete -- Revised Final / Canonical Edition

Prepared statements can reduce repeated parse/planning work. PostgreSQL may use custom plans sensitive to parameter values or generic plans intended to perform acceptably across executions. Highly skewed parameter distributions can make one strategy materially better for some values.

When latency differs sharply by bind value, compare plans for representative parameter classes, statistics, skew, and application prepare behavior. Use `plan_cache_mode` only as a controlled diagnostic or deliberately validated policy; forcing one plan type can improve one workload and harm another.

Connection poolers and drivers can change prepared-statement behavior, so include the real application path in testing.
