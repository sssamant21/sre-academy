# 6.2 -- Parser, Analyzer, Rewriter, Planner, and Executor

**Status:** Complete -- Revised Final / Canonical Edition

The parser checks SQL syntax and builds a parse tree. Semantic analysis resolves names, types, operators, functions, and privileges into a query representation. The rewrite system applies rules such as view expansion. The planner explores legal strategies and estimates their costs. The executor runs the selected plan under PostgreSQL transaction, MVCC, lock, memory, and I/O semantics.

A failure or delay should be mapped to the responsible phase. Syntax/name errors are not planner defects; poor row estimates are not executor defects; lock waits are not fixed by changing scan cost constants. Production troubleshooting should preserve this separation.

Operational controls include statement timeouts, lock-timeout strategy where appropriate, query logging/telemetry, plan capture, statistics maintenance, and application-side cancellation/retry behavior. Avoid enabling highly verbose diagnostics globally without measuring overhead and information exposure.
