# 6.20 -- Slow Query Identification and Performance Baselines

**Status:** Complete -- Revised Final / Canonical Edition

A slow-query program needs baselines by query identity/workload class: call rate, p50/p95/p99 latency where observability supports it, total database time, rows, reads/hits, temp I/O, WAL, CPU/I/O correlation, and plan fingerprints.

Prioritize both individually slow queries and high-frequency moderate queries with large aggregate cost. Compare current behavior against the same workload period, deployment version, data volume, and infrastructure state.

Logging thresholds can help but may add I/O and expose SQL values. Use sampling/telemetry policies appropriate to production and security requirements.
