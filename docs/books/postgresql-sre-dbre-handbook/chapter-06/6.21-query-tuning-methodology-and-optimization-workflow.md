# 6.21 -- Query Tuning Methodology and Optimization Workflow

**Status:** Complete -- Revised Final / Canonical Edition

Canonical workflow:
1. Define the user/SLO symptom.
2. Identify query/queryid and workload class.
3. Capture baseline latency, calls, rows, waits, buffers, temp I/O, WAL, CPU/I/O.
4. Capture a safe plan and representative parameters.
5. Compare estimated versus actual rows where safe.
6. Identify the dominant cost/wait.
7. Check statistics and data skew.
8. Review SQL, indexes, joins, partitioning, memory/spill, parallelism, and concurrency.
9. Change one controlled variable where practical.
10. Benchmark correctness and performance under representative load.
11. Define rollout, observability, abort criteria, and rollback.
12. Verify fleet-wide effects after deployment.

Optimization that improves one query while degrading system throughput is not a successful production change.
