# 6.22 -- Plan Regression, Statistics Drift, and Performance Instability

**Status:** Complete -- Revised Final / Canonical Edition

Plan regressions can follow data growth/skew, statistics changes, schema/index changes, configuration, PostgreSQL upgrades, parameter-value shifts, memory/I/O changes, or application SQL changes.

Capture before/after query text/queryid, plan structure, estimates/actuals, statistics timing, data distribution, settings, indexes, and infrastructure telemetry. Avoid assuming that a changed plan is automatically the cause; validate timing and resource evidence.

Production releases involving upgrades, indexes, partitioning, major statistics changes, or planner settings should include representative query-plan regression testing and rollback criteria.
