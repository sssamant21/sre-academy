# 6.24 -- Query Performance Troubleshooting and Production Runbooks

**Status:** Complete -- Revised Final / Canonical Edition

Incident runbook:
1. Confirm application/SLO impact and blast radius.
2. Identify top active/waiting and highest-impact query groups.
3. Classify CPU, I/O, lock, memory/spill, connection, replication, or client/network pressure.
4. Capture low-risk telemetry and plans.
5. Check plan/estimate changes, statistics, schema/index deployments, batch jobs, and data growth.
6. Protect capacity: throttle/pause optional workloads through approved controls.
7. Cancel individual harmful queries only after ownership/transaction impact review.
8. Apply the lowest-risk reversible mitigation.
9. Validate recovery across database and application SLOs.
10. Perform root-cause analysis and permanent tuning with regression tests.

Do not restart PostgreSQL, drop indexes, globally raise memory, disable planner methods, or kill all sessions as generic slow-query remediation.
