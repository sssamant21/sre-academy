# 6.8 -- EXPLAIN Fundamentals and Plan Trees

**Status:** Complete -- Revised Final / Canonical Edition

`EXPLAIN` shows the plan selected by PostgreSQL without executing the statement. Read plans as trees: child nodes feed parent nodes. Important fields include node type, startup cost, total cost, estimated rows, width, filters, join conditions, sort keys, and parallel nodes.

```sql
EXPLAIN
SELECT * FROM orders WHERE customer_id = 1001;
```

A plan should be interpreted in workload context. A sequential scan is not inherently bad and an index scan is not inherently good. Consider relation size, selectivity, cache state, concurrency, and total work. Save representative plans as baselines for important queries so regressions can be compared structurally.
