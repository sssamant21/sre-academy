# 7.10 — Partial Indexes and Selective Workloads

**Status:** Complete — Revised Final / Canonical Edition

## Purpose

Reduce index footprint and maintenance by indexing only the subset important to recurring workloads.

## Canonical Guidance

```sql
CREATE INDEX idx_orders_unprocessed
ON orders (created_at)
WHERE processed_at IS NULL;
```

Partial indexes are useful when a stable predicate identifies a relatively small, frequently queried subset. The planner must be able to establish that the query predicate implies the index predicate; parameterized or differently expressed conditions can limit applicability.

## Production Review

Validate subset size, query-predicate consistency, data-distribution drift, uniqueness requirements, and maintenance savings. Monitor whether the indexed subset grows until it no longer remains selective.

## Production Rules

1. Partial indexes encode workload assumptions.
2. Predicate matching and implication matter.
3. Monitor distribution drift.
4. Use partial unique indexes when business uniqueness applies only to a subset.
