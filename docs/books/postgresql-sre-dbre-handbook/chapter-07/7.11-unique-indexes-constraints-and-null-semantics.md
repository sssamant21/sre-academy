# 7.11 — Unique Indexes, Constraints, and NULL Semantics

**Status:** Complete — Revised Final / Canonical Edition

## Purpose

Connect uniqueness enforcement with index architecture and production data integrity.

## Canonical Guidance

PostgreSQL uses unique indexes to enforce unique constraints and primary keys. Modern PostgreSQL also supports `NULLS NOT DISTINCT` where required by the business rule.

```sql
CREATE UNIQUE INDEX ux_accounts_external_id
ON accounts (external_id);
```

Prefer declarative constraints when modeling relational integrity because they communicate intent to PostgreSQL and tooling. Use direct unique indexes for cases such as expression or partial uniqueness where appropriate.

## Production Review

Before creating uniqueness on existing data, detect duplicates and define remediation. Concurrent index-building strategies may be needed for large production tables, followed by constraint attachment when applicable.

## Production Rules

1. Uniqueness is a correctness requirement, not only a performance feature.
2. Define intended NULL semantics explicitly.
3. Validate existing data before enforcement.
4. Plan lock and build behavior for large relations.
