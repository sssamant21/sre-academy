# 7.12 — Covering Indexes, INCLUDE, and Index-Only Scans

**Status:** Complete — Revised Final / Canonical Edition

## Purpose

Design covering indexes that can reduce heap access without creating unnecessarily wide keys.

## Canonical Guidance

`INCLUDE` stores non-key payload columns. An index-only scan can return data from the index when the index type supports it and heap-page visibility permits avoiding heap visits.

```sql
CREATE INDEX idx_orders_customer_cover
ON orders (customer_id)
INCLUDE (status, total_amount);
```

Index-only performance depends on visibility-map state; a covering index does not guarantee zero heap fetches. Wide payloads increase index size and write cost.

## Monitoring

Use `EXPLAIN (ANALYZE, BUFFERS)` and inspect `Heap Fetches`, plan shape, latency, and index growth. Correlate poor index-only behavior with vacuum/visibility conditions rather than blindly adding columns.

## Production Rules

1. `INCLUDE` columns are payload, not search keys.
2. Cover only stable, valuable query families.
3. Index-only scans depend on visibility as well as coverage.
4. Avoid turning indexes into copies of the table.
