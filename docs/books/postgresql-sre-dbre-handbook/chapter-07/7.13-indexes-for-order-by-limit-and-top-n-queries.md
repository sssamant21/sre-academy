# 7.13 — Indexes for ORDER BY, LIMIT, and Top-N Queries

**Status:** Complete — Revised Final / Canonical Edition

## Purpose

Exploit ordered indexes for latency-sensitive sorting and Top-N access patterns.

## Canonical Guidance

B-tree indexes can produce ordered output and may eliminate or reduce explicit sorting. This is particularly valuable with selective predicates and small `LIMIT` values.

```sql
CREATE INDEX idx_events_tenant_created
ON events (tenant_id, created_at DESC);

SELECT id, created_at
FROM events
WHERE tenant_id = 42
ORDER BY created_at DESC
LIMIT 50;
```

## Production Review

Match equality predicates, ordering direction, null ordering, and pagination model. Compare keyset pagination with large `OFFSET` workloads where appropriate. Do not add a dedicated sorting index without measuring frequency and latency impact.

## Production Rules

1. Design ordering indexes around complete query shapes.
2. Top-N queries can gain disproportionate benefit from matching order.
3. Validate sort elimination in actual plans.
