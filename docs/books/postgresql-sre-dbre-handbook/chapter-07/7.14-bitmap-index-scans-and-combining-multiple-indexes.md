# 7.14 — Bitmap Index Scans and Combining Multiple Indexes

**Status:** Complete — Revised Final / Canonical Edition

## Purpose

Understand how PostgreSQL combines indexes at execution time without a persistent bitmap index access method.

## Architecture

The planner can combine multiple index scans into bitmaps and use a Bitmap Heap Scan to visit matching heap pages. This supports useful AND/OR combinations but generally loses native index ordering and adds bitmap construction work.

```sql
EXPLAIN (ANALYZE, BUFFERS)
SELECT * FROM orders
WHERE customer_id = 42 AND status = 'OPEN';
```

## Design Guidance

Do not automatically replace two useful single-column indexes with a composite index, or vice versa. Compare query frequency, selectivity, ordering needs, write cost, and plan stability.

## Production Rules

1. PostgreSQL bitmap scans are execution strategies, not a separate on-disk bitmap index type.
2. Multiple indexes can be combined.
3. Composite indexes can still be better for frequent, ordered, highly specific query families.
