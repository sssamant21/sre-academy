# 7.16 — Index Selectivity, Statistics, and Planner Decisions

**Status:** Complete — Revised Final / Canonical Edition

## Purpose

Connect index design to PostgreSQL cardinality estimation and cost-based planning.

## Canonical Guidance

An index can be perfectly constructed yet unused because the planner estimates that another path is cheaper. Statistics, data distribution, correlation, predicate selectivity, table size, cache assumptions, and cost parameters influence that decision.

```sql
ANALYZE orders;

SELECT attname, n_distinct, correlation
FROM pg_stats
WHERE tablename = 'orders';
```

## Troubleshooting

When a seemingly useful index is ignored, inspect estimated versus actual rows, stale statistics, skew, cross-column dependencies, casts, functions, operator compatibility, and result-set size before changing planner switches.

## Production Rules

1. Do not force index scans as the first troubleshooting action.
2. Correct statistics and query semantics before tuning planner costs.
3. Evaluate estimated versus actual cardinality at each important plan node.
