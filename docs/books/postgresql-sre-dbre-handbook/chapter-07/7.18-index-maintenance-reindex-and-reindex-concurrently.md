# 7.18 — Index Maintenance, REINDEX, and REINDEX CONCURRENTLY

**Status:** Complete — Revised Final / Canonical Edition

## Purpose

Operate index rebuilds as controlled reliability changes rather than routine folklore.

## Canonical Guidance

`REINDEX` reconstructs an index and is appropriate for specific corruption, bloat, collation, or structural remediation cases. `REINDEX CONCURRENTLY` can reduce blocking for supported objects but increases duration and resource consumption.

```sql
REINDEX INDEX CONCURRENTLY idx_orders_customer;
```

## Production Review

Confirm why a rebuild is needed. Size alone is insufficient evidence. Estimate temporary disk requirements, WAL, replication lag, I/O saturation, lock behavior, and duration. Validate backup/recovery posture before large maintenance.

## Production Rules

1. Reindex for evidence-backed reasons.
2. Ensure free-space headroom for rebuild artifacts.
3. Monitor replicas and storage throughout the operation.
4. Avoid mass concurrent rebuilds without capacity modeling.
