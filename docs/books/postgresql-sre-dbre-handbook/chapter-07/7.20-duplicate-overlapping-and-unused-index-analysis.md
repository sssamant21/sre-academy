# 7.20 — Duplicate, Overlapping, and Unused Index Analysis

**Status:** Complete — Revised Final / Canonical Edition

## Purpose

Reduce unnecessary index overhead safely.

## Canonical Guidance

Exact duplicates are usually candidates for consolidation, but apparently overlapping indexes can differ in uniqueness, predicates, expressions, operator classes, ordering, included columns, or workload purpose. `idx_scan = 0` is evidence to investigate, not automatic permission to drop.

## Review Checklist

- constraint/primary-key dependency
- uniqueness semantics
- partial predicate
- expression/opclass/collation
- column order and INCLUDE payload
- reporting/monthly/seasonal workload
- replica-specific query patterns
- statistics reset date

## Safe Removal Runbook

Observe through a representative workload window, map dependencies, capture baseline latency and write overhead, use change control, remove conservatively, and monitor regressions with a rollback plan.

## Production Rules

1. Never drop an index solely because `idx_scan` is zero.
2. Constraint-backed indexes require integrity analysis.
3. Redundant-index cleanup can materially reduce write and storage amplification.
