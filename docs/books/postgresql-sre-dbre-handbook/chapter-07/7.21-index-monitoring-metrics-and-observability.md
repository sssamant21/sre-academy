# 7.21 — Index Monitoring, Metrics, and Observability

**Status:** Complete — Revised Final / Canonical Edition

## Purpose

Build an observability model that links index behavior to query latency, writes, storage, vacuum, and planner decisions.

## Metrics

```sql
SELECT relname, indexrelname, idx_scan, idx_tup_read, idx_tup_fetch
FROM pg_stat_user_indexes
ORDER BY idx_scan DESC;
```

Track index/table size, growth rate, scan counts, tuple read/fetch patterns, query latency, plan changes, cache behavior, write volume, WAL rate, vacuum health, and storage latency. Statistics counters are cumulative and can reset, so preserve time-series history externally.

## SRE Model

Query -> Plan -> Index access -> Heap access -> Buffer/cache -> Storage -> WAL/replication

Observability should preserve this causal chain. An index metric without query and infrastructure context is rarely sufficient for diagnosis.

## Production Rules

1. Store historical index metrics.
2. Alert on trends and impact, not isolated counters.
3. Correlate index changes with deployment and schema-change events.
