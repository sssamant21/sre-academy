# 7.22 — Index Alerting and Reliability Thresholds

**Status:** Complete — Revised Final / Canonical Edition

## Purpose

Define actionable alerts for index-related reliability risks without brittle universal thresholds.

## Alert Classes

Use alerts for invalid indexes after failed maintenance, unexpected index growth, storage runway, severe index-related query regression, sustained write/WAL amplification after schema changes, replica lag during index operations, and maintenance operations approaching capacity limits.

Thresholds should be workload-specific. A 500 GB index can be healthy on one system and dangerous on another; runway, growth rate, latency, IOPS, maintenance duration, and recovery requirements provide better context.

## Production Rules

1. Prefer predictive alerts over fixed-size alarms.
2. Page on user/reliability impact; ticket on optimization opportunities.
3. Attach a runbook, owner, evidence query, and remediation boundary to each alert.
4. Avoid automated destructive index changes from a single signal.
