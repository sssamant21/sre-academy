# 7.23 — Index Performance Troubleshooting

**Status:** Complete — Revised Final / Canonical Edition

## Purpose

Provide a repeatable SRE/DBRE diagnostic path for index-related performance problems.

## Runbook

1. Confirm the user-visible symptom and time window.
2. Identify query families and plan changes.
3. Capture `EXPLAIN (ANALYZE, BUFFERS)` safely.
4. Compare estimated versus actual rows.
5. Verify predicate/operator/index compatibility.
6. Check statistics and distribution.
7. Inspect index/table size and storage latency.
8. Check write load, vacuum, cache, WAL, and replica effects.
9. Test candidate changes outside production.
10. Deploy one controlled change and measure.

## Common Misdiagnoses

- "Index exists, therefore planner must use it."
- "Sequential scan always means a missing index."
- "Large index means bloat."
- "More indexes always improve reads."
- "`idx_scan = 0` means safe to drop."

## Production Rules

Troubleshoot from query behavior outward. Avoid planner disabling, mass index creation, or rebuilds until root-cause evidence supports them.
