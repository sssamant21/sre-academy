# 7.24 — Index Automation and Production Operational Runbooks

**Status:** Complete — Revised Final / Canonical Edition

## Purpose

Automate index observation and controlled maintenance while keeping destructive decisions behind strong safeguards.

## Automation Candidates

Automate inventory, size/growth collection, duplicate-candidate reports, low-usage candidate reports, invalid-index detection, query-plan regression correlation, build/reindex progress monitoring, storage-runway forecasts, and post-change validation.

## Guardrails

Do not automatically drop, rebuild, or create production indexes solely from heuristic recommendations. Require workload evidence, dependency checks, resource preflight, change controls, rollback, and post-change validation.

## Operational Runbook Template

- Objective and owner
- Affected database/table/index
- Baseline query and resource metrics
- DDL and execution method
- Lock/I/O/WAL/storage estimates
- Replica and HA impact
- Abort criteria
- Rollback
- Validation queries
- Observation period

## Production Rules

1. Automate evidence collection aggressively.
2. Automate destructive actions conservatively.
3. Every large index operation needs capacity and replication preflight.
4. Preserve audit history for index lifecycle decisions.
