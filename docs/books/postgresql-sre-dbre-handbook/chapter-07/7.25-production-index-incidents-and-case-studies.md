# 7.25 — Production Index Incidents and Case Studies

**Status:** Complete — Revised Final / Canonical Edition

## Purpose

Translate index theory into production incident patterns and preventive controls.

## Case Studies

**Missing composite index:** a tenant/time Top-N API benefits from a workload-aligned `(tenant_id, created_at DESC)` index after plan validation.

**Over-indexing:** overlapping indexes increase write latency, WAL, storage, and vacuum work; dependency-aware consolidation restores efficiency.

**Failed concurrent build:** an invalid index remains after failure; the runbook diagnoses the cause, removes/retries safely, and validates storage and replicas.

**BRIN effectiveness drift:** out-of-order loads reduce physical correlation and increase blocks read; remediation starts with data-layout analysis.

**Covering index too wide:** excessive `INCLUDE` columns reduce heap access but inflate write and storage cost; redesign targets the highest-value query family.

**Stale statistics blamed on index:** changed distribution causes a plan shift; statistics/cardinality remediation fixes the root cause rather than forcing scans.

## Final SRE/DBRE Principles

- Index design is workload engineering.
- Index lifecycle is capacity engineering.
- Index maintenance is change management.
- Troubleshooting begins with plans and evidence.
- Reliability balances read latency, write cost, storage, WAL, replication, and recovery.
