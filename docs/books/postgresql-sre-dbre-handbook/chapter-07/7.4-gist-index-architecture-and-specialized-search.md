# 7.4 — GiST Index Architecture and Specialized Search

**Status:** Complete — Revised Final / Canonical Edition

## Purpose

Explain GiST as an extensible indexing framework for operator classes such as geometric, range, nearest-neighbor, and extension-defined searches.

## Canonical Guidance

GiST is not one fixed search algorithm. Operator classes define how values are represented and searched. Design therefore starts with the data type and operators used by the workload.

```sql
CREATE INDEX idx_locations_gist
ON locations USING GIST (geom);
```

## Production Review

Validate the exact operator class, selectivity, lossy/recheck behavior where applicable, build cost, index growth, and extension dependencies. Benchmark representative predicates rather than assuming GiST improves all searches on a supported type.

## Operations

Monitor execution plans, heap rechecks, latency, index size, maintenance behavior, and extension/version compatibility. During upgrades, confirm that required operator classes and extensions are supported and tested.

## Production Rules

1. GiST usefulness is operator-class dependent.
2. Test real spatial/range/similarity predicates.
3. Treat extension-backed indexes as part of upgrade and recovery planning.
