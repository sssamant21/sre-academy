# 7.5 — SP-GiST Index Architecture and Partitioned Search Spaces

**Status:** Complete — Revised Final / Canonical Edition

## Purpose

Cover SP-GiST for data structures naturally represented by partitioned search spaces.

## Architecture

SP-GiST supports operator classes that map data into non-balanced partitioning structures such as tries, quadtrees, and related schemes. Applicability is driven by supported data types and operators, not by a generic promise of faster indexing.

```sql
CREATE INDEX idx_network_spgist
ON network_objects USING SPGIST (address);
```

## Production Review

Confirm operator-class support, predicate compatibility, distribution characteristics, index size, build time, and observed plans. Compare against B-tree or GiST where both are viable.

## Reliability Guidance

Specialized index choices should be documented with the workload they serve. Monitor whether the query mix changes enough to invalidate the original design.

## Production Rules

1. Use SP-GiST only for compatible operator classes and search patterns.
2. Benchmark alternatives.
3. Document the design rationale for future SRE/DBRE teams.
