# 7.8 — Multicolumn Index Design and Column Ordering

**Status:** Complete — Revised Final / Canonical Edition

## Purpose

Design multicolumn indexes from predicate structure, selectivity, ordering, and access-method semantics.

## Canonical Guidance

For multicolumn B-tree indexes, equality constraints on leading columns and an inequality on the first non-equality column are especially effective at limiting the scanned portion. Current PostgreSQL can also use B-tree skip scan in suitable distributions, so the simplistic statement that an index can never help without the first column is incorrect.

```sql
CREATE INDEX idx_orders_customer_created
ON orders (customer_id, created_at DESC);
```

Map query families first: equality predicates, ranges, sort requirements, returned columns, and frequency. Avoid wide indexes built merely to cover every variation.

## Production Rules

1. Column order is workload-dependent.
2. Leading-column behavior matters strongly for B-tree, while access methods differ.
3. Skip scan is a planner optimization, not a reason to ignore deliberate key order.
4. Prefer useful indexes over overlapping permutations.
