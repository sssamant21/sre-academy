# 7.9 — Expression and Functional Indexes

**Status:** Complete — Revised Final / Canonical Edition

## Purpose

Use expression indexes when queries repeatedly filter or constrain a deterministic transformation rather than the base column value.

## Canonical Guidance

```sql
CREATE INDEX idx_users_lower_email
ON users (lower(email));

SELECT * FROM users WHERE lower(email) = lower('User@example.com');
```

Expression indexes can accelerate transformed predicates and can enforce uniqueness on expressions. Their values must be maintained during inserts and non-HOT updates, so read benefit must justify write overhead. Functions/operators used in index definitions must satisfy PostgreSQL immutability requirements.

## Production Review

Ensure query expressions structurally match the indexed expression. Check collation and semantic requirements. Avoid incorrectly labeling environment-dependent functions immutable just to permit indexing; that can compromise index correctness.

## Production Rules

1. Index the expression actually used by stable query families.
2. Treat immutability as a correctness contract.
3. Measure write amplification and HOT-update consequences.
