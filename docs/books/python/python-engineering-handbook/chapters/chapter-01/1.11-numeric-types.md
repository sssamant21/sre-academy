# Chapter 1 — Python Fundamentals and Development Environment

## 1.11 — Numeric Types

**Edition:** Revised Final / Canonical  
**Target Runtime:** Python 3.14

### Learning Objectives

After completing this section, you will be able to:

- distinguish Python's core numeric types and choose them according to data semantics;
- work safely with integers, floating-point values, decimal values, and complex numbers;
- explain arbitrary-precision integer behavior and floating-point approximation;
- use arithmetic, division, modulo, exponentiation, rounding, and conversion correctly;
- handle infinity, NaN, and non-finite values at production boundaries;
- understand mixed built-in numeric arithmetic and numeric comparisons;
- apply numeric types to percentages, retries, capacity calculations, financial values, and storage units;
- validate numeric input from external systems;
- recognize numeric resource-exhaustion and correctness risks;
- troubleshoot common production numeric failures.

The central engineering principle is:

> **Numeric correctness requires choosing the representation that matches the quantity being modeled and enforcing that quantity's domain rules at system boundaries.**

A useful first distinction is:

```text
exact integral quantity
          vs
approximate real quantity
          vs
exact decimal quantity
```

Examples:

```text
request count       → int
CPU utilization     → float
financial amount    → Decimal or integer minor units
```

---

## 1.11.1 Python's Core Numeric Types

Python provides several built-in numeric types:

```python
count = 42
ratio = 0.875
signal = 3 + 4j

print(type(count))
print(type(ratio))
print(type(signal))
```

Output:

```text
<class 'int'>
<class 'float'>
<class 'complex'>
```

For exact base-10 decimal arithmetic, Python's standard library provides `decimal.Decimal`:

```python
from decimal import Decimal

price = Decimal("19.95")
```

These types model different kinds of quantities. Choosing a type merely because it can hold a value is not enough.

A production-oriented model is:

```text
representation
      +
precision
      +
rounding
      +
range
      +
finiteness
      +
units
      +
validation
      +
resource limits
```

---

## 1.11.2 Integers — `int`

Use `int` for exact integral quantities:

```python
replicas = 3
requests = 1_250_000
port = 5432
```

Typical examples include:

- counts;
- sequence numbers;
- retry attempts;
- byte counts;
- identifiers that are genuinely numeric;
- timestamps represented as integral units;
- integer configuration values.

Integer arithmetic is exact at the language level:

```python
total = 10 + 20
product = 12 * 25

print(total)
print(product)
```

Output:

```text
30
300
```

Do not use an integer merely because a business identifier contains digits. A postal code, account number, or externally defined identifier may semantically be text.

---

## 1.11.3 Arbitrary-Precision Integers

Python integers are not restricted to fixed 32-bit or 64-bit ranges.

```python
value = 10 ** 100

print(value)
```

Python can represent this integer exactly, subject to available memory and computational resources.

This does **not** mean integer operations have unlimited operational cost.

Large integers require more:

- memory;
- CPU;
- serialization space;
- conversion time.

For example:

```python
value = 2 ** 1_000_000
```

is valid Python, but calculations involving user-controlled magnitudes or exponents can become resource-exhaustion risks.

Production rule:

> **Treat arbitrary precision as a correctness capability, not as permission to accept unbounded numeric input.**

---

## 1.11.4 Integer Literal Forms

Python supports several integer literal bases:

```python
decimal_value = 255
binary_value = 0b11111111
octal_value = 0o377
hex_value = 0xFF

print(decimal_value)
print(binary_value)
print(octal_value)
print(hex_value)
```

All represent the same integer:

```text
255
```

These forms are useful when the representation carries engineering meaning.

Examples:

```python
permission_mask = 0o640
flags = 0b1010
color_mask = 0xFF
```

Use the representation that best communicates the domain.

---

## 1.11.5 Numeric Literal Separators

Underscores improve readability:

```python
requests = 1_000_000
memory_bytes = 16_000_000_000
mask = 0xFFFF_FFFF
```

The underscores do not change the numeric value:

```python
print(1_000_000 == 1000000)
```

Output:

```text
True
```

Use separators when they make scale or grouping easier to verify.

---

## 1.11.6 Floating-Point Numbers — `float`

Use `float` for quantities where binary floating-point approximation is appropriate:

```python
cpu_utilization = 73.25
latency_ms = 12.7
load_average = 1.84
```

Python floating-point numbers are usually implemented using the platform's C `double` representation. Their exact precision and representation characteristics are platform-dependent and can be inspected through `sys.float_info`.

```python
import sys

print(sys.float_info)
```

Floating-point values are extremely useful for scientific calculations, measurements, telemetry, ratios, and many performance metrics.

They should not automatically be used for quantities that require exact decimal arithmetic.

---

## 1.11.7 Binary Floating-Point Approximation

Many decimal fractions cannot be represented exactly in binary floating point.

```python
print(0.1 + 0.2)
```

A typical result is:

```text
0.30000000000000004
```

This is not a Python arithmetic defect. It follows from representing many base-10 fractions using a finite binary representation.

The same issue exists in most systems using IEEE-style binary floating-point arithmetic.

A useful mental model is:

```text
decimal source value
        ↓
nearest representable binary float
        ↓
arithmetic
        ↓
formatted decimal representation
```

---

## 1.11.8 Floating-Point Equality

Avoid assuming that mathematically equivalent floating-point calculations will always produce exactly equal binary results.

Instead of:

```python
result = 0.1 + 0.2

if result == 0.3:
    print("equal")
```

use a tolerance appropriate to the domain.

Python provides `math.isclose()`:

```python
import math

result = 0.1 + 0.2

print(math.isclose(result, 0.3))
```

Output:

```text
True
```

For production systems, tolerance is a domain decision.

Consider:

- expected magnitude;
- measurement precision;
- accumulated error;
- absolute versus relative tolerance;
- consequences of false equality.

Do not copy one tolerance value into every application without understanding what it means.

---

## 1.11.9 Exact Decimal Arithmetic

For quantities requiring decimal semantics, use `decimal.Decimal` or another representation designed for the domain.

```python
from decimal import Decimal

price = Decimal("19.95")
tax = Decimal("1.60")

total = price + tax

print(total)
```

Output:

```text
21.55
```

When the original value is decimal text, construct `Decimal` from a string:

```python
amount = Decimal("0.1")
```

Avoid this when exact decimal input semantics are intended:

```python
amount = Decimal(0.1)
```

The `float` has already approximated `0.1` before `Decimal` receives it.

For financial systems, another common design is integer minor units:

```python
price_cents = 1995
tax_cents = 160
total_cents = price_cents + tax_cents
```

The correct model depends on the business rules, currencies, scale, rounding policy, and integration contracts.

---

## 1.11.10 Arithmetic Operators

Python's common arithmetic operators include:

| Operator | Meaning |
|---|---|
| `+` | Addition |
| `-` | Subtraction |
| `*` | Multiplication |
| `/` | True division |
| `//` | Floor division |
| `%` | Modulo |
| `**` | Exponentiation |

Example:

```python
a = 10
b = 3

print(a + b)
print(a - b)
print(a * b)
print(a / b)
print(a // b)
print(a % b)
print(a ** b)
```

Division by zero is an error:

```python
10 / 0
10 // 0
10 % 0
```

These operations raise `ZeroDivisionError`.

Production systems should validate or otherwise control divisors when zero is possible, especially in:

- rates;
- ratios;
- percentages;
- averages;
- capacity calculations;
- telemetry.

---

## 1.11.11 True Division — `/`

The `/` operator performs true division:

```python
print(10 / 4)
```

Output:

```text
2.5
```

Integer operands can therefore produce a `float`:

```python
result = 10 / 2

print(result)
print(type(result))
```

Output:

```text
5.0
<class 'float'>
```

Do not use `/` when the required result is specifically floor division or an exact quotient/remainder decomposition.

---

## 1.11.12 Floor Division — `//`

The `//` operator performs floor division:

```python
print(10 // 3)
```

Output:

```text
3
```

A common mistake is describing `//` as truncation toward zero.

For negative values:

```python
print(-10 // 3)
```

Output:

```text
-4
```

The mathematical quotient is approximately `-3.333...`; flooring moves toward negative infinity.

This distinction matters in:

- bucket calculations;
- pagination;
- time-window calculations;
- coordinate systems;
- partitioning algorithms.

---

## 1.11.13 Modulo — `%`

Modulo returns the remainder associated with floor division:

```python
print(10 % 3)
```

Output:

```text
1
```

For appropriate integer operands:

```text
x == (x // y) * y + (x % y)
```

For a nonzero result, Python's modulo result has the sign of the divisor.

Example:

```python
print(-10 % 3)
print(10 % -3)
```

Output:

```text
2
-2
```

For floating-point operands, rounding effects mean reconstructed results should not be assumed to be exactly equal in every case.

Modulo is useful for:

- cyclic counters;
- partition selection;
- parity tests;
- periodic scheduling logic.

---

## 1.11.14 Exponentiation — `**`

Use `**` for exponentiation:

```python
print(2 ** 10)
```

Output:

```text
1024
```

Python's `pow()` provides equivalent two-argument behavior:

```python
print(pow(2, 10))
```

For integer modular exponentiation:

```python
print(pow(2, 10, 1000))
```

Output:

```text
24
```

The three-argument form is useful because it computes modular exponentiation without first materializing the entire power.

User-controlled exponents should still be bounded according to resource and domain constraints.

---

## 1.11.15 Unary Numeric Operators

Python supports unary numeric operations:

```python
value = 10

print(+value)
print(-value)
```

Output:

```text
10
-10
```

Unary `-` negates a numeric value.

Unary `+` generally returns the numeric value according to the type's unary-plus behavior and is less frequently needed in ordinary application code.

Bitwise inversion `~` applies to integers and is discussed with bitwise operations later in this section.

---

## 1.11.16 Numeric Conversion

Built-in conversion functions include:

```python
int("42")
float("3.14")
complex("2+3j")
```

Examples:

```python
port = int("5432")
threshold = float("0.85")

print(port)
print(threshold)
```

Conversion answers:

```text
Can this representation be converted?
```

It does **not** answer:

```text
Is this value acceptable for the application?
```

For example:

```python
port = int("-1")
```

succeeds as a conversion but does not produce a valid TCP port.

Production boundary:

```text
external representation
        ↓
conversion/parsing
        ↓
numeric value
        ↓
domain validation
```

---

## 1.11.17 Float-to-Integer Conversion

`int()` converts a floating-point value by truncating toward zero:

```python
print(int(3.9))
print(int(-3.9))
```

Output:

```text
3
-3
```

This differs from mathematical floor:

```python
import math

print(math.floor(-3.9))
```

Output:

```text
-4
```

And ceiling:

```python
print(math.ceil(-3.9))
```

Output:

```text
-3
```

Choose the operation according to the required semantics rather than treating them as interchangeable.

---

## 1.11.18 Mixed Numeric Arithmetic

For the built-in numeric types, a useful widening model is:

```text
int → float → complex
```

Examples:

```python
print(2 + 0.5)
print(2 + 3j)
print(2.5 + 3j)
```

This is a model of Python's mixed built-in numeric arithmetic rules, not a general coercion hierarchy for arbitrary user-defined or third-party numeric classes.

Mixing `Decimal` and binary floating-point values requires particular care and should not be treated as ordinary widening.

Keep numeric domains explicit when exactness matters.

---

## 1.11.19 `abs()`

`abs()` returns the absolute value or magnitude appropriate to the numeric type:

```python
print(abs(-10))
print(abs(-3.5))
```

Output:

```text
10
3.5
```

For a complex number:

```python
print(abs(3 + 4j))
```

Output:

```text
5.0
```

For complex numbers, `abs()` returns the magnitude.

---

## 1.11.20 `round()`

`round()` rounds a value to a requested precision:

```python
print(round(3.14159, 2))
```

Output:

```text
3.14
```

For Python's built-in real numeric types, when a value is exactly halfway between two choices at the requested precision, `round()` chooses the even one.

```python
print(round(2.5))
print(round(3.5))
```

Output:

```text
2
4
```

Binary floating-point representation still matters. A decimal value that appears halfway when written may not be represented as an exact halfway binary value.

For regulated financial or accounting calculations, use an explicitly defined decimal rounding policy rather than relying on casual assumptions about `round()`.

---

## 1.11.21 `divmod()`

`divmod()` returns the quotient and remainder together:

```python
quotient, remainder = divmod(10, 3)

print(quotient)
print(remainder)
```

Output:

```text
3
1
```

This is useful when both results are required.

Example:

```python
total_seconds = 3675

minutes, seconds = divmod(total_seconds, 60)
hours, minutes = divmod(minutes, 60)

print(hours, minutes, seconds)
```

Output:

```text
1 1 15
```

---

## 1.11.22 `min()` and `max()`

Use `min()` and `max()` to find extrema:

```python
latencies = [12.4, 8.7, 19.2, 11.0]

print(min(latencies))
print(max(latencies))
```

Be aware that calling these functions on an empty iterable without a suitable default raises `ValueError`.

Production code should define what an empty dataset means instead of inventing an arbitrary numeric result.

---

## 1.11.23 `sum()` and Accurate Float Summation

Use `sum()` for ordinary summation:

```python
values = [10, 20, 30]

print(sum(values))
```

Output:

```text
60
```

For floating-point workloads where accumulated rounding error matters, `math.fsum()` provides a more accurate floating-point summation algorithm:

```python
import math

values = [0.1] * 10

print(sum(values))
print(math.fsum(values))
```

Choose the method according to the required accuracy and workload.

For exact decimal quantities, use a representation such as `Decimal` rather than expecting a float summation algorithm to create decimal exactness.

---

## 1.11.24 Infinity

Floating-point values can represent positive and negative infinity:

```python
positive = float("inf")
negative = float("-inf")

print(positive)
print(negative)
```

Infinity can arise intentionally or through some numerical operations and external data sources.

Do not assume that a successfully parsed `float` is finite.

---

## 1.11.25 NaN — Not a Number

Floating point also supports NaN:

```python
value = float("nan")

print(value)
```

NaN has unusual comparison behavior:

```python
print(value == value)
```

Output:

```text
False
```

Therefore, do not detect NaN using equality.

Use:

```python
import math

print(math.isnan(value))
```

NaN can silently propagate through calculations and should be handled according to the data contract.

---

## 1.11.26 Checking Finite Values

For many application inputs, a valid float must be finite.

Use:

```python
import math

value = 73.5

print(math.isfinite(value))
```

Related functions include:

```python
math.isnan(value)
math.isinf(value)
math.isfinite(value)
```

A strong validation boundary for a percentage, latency, rate, or capacity value often includes:

```text
correct type
      +
not bool when bool is semantically invalid
      +
finite
      +
within domain range
```

---

## 1.11.27 Complex Numbers

Python supports complex numbers:

```python
value = 3 + 4j

print(value.real)
print(value.imag)
print(abs(value))
```

Output:

```text
3.0
4.0
5.0
```

Complex numbers are useful in domains such as:

- signal processing;
- electrical engineering;
- scientific computing;
- mathematical modeling.

Ordinary ordering comparisons are not defined:

```python
(1 + 2j) < (3 + 4j)
```

raises `TypeError`.

Use domain-specific comparisons such as magnitude when appropriate.

---

## 1.11.28 Bitwise Operations

Integers support bitwise operators:

| Operator | Meaning |
|---|---|
| `&` | AND |
| `|` | OR |
| `^` | XOR |
| `~` | Invert |

Example:

```python
read = 0b001
write = 0b010
execute = 0b100

permissions = read | write

print(bin(permissions))
```

Output:

```text
0b11
```

Test a flag:

```python
if permissions & write:
    print("write enabled")
```

Bitwise operations are appropriate for:

- masks;
- protocol flags;
- compact state representations;
- systems programming.

Prefer named constants over unexplained numeric masks.

---

## 1.11.29 Shift Operations

Integers support left and right shifts:

```python
print(1 << 3)
print(8 >> 2)
```

Output:

```text
8
2
```

For nonnegative integers, shifting left by `n` positions corresponds to multiplication by `2 ** n`.

Shifts are useful for:

- bit masks;
- binary protocols;
- low-level data layouts;
- powers-of-two calculations.

Do not replace readable ordinary arithmetic with shifts merely for perceived performance.

---

## 1.11.30 Numeric Comparisons

Numeric values support comparisons:

```python
print(10 < 20)
print(10 <= 10)
print(20 > 10)
print(20 >= 20)
print(10 == 10.0)
print(10 != 11)
```

Python also supports chained comparisons:

```python
percentage = 75

if 0 <= percentage <= 100:
    print("valid")
```

This is usually clearer than:

```python
if percentage >= 0 and percentage <= 100:
    ...
```

Remember that equality across numeric types does not mean the types have identical semantics.

For floating-point approximation, use tolerance-based comparison where required.

## 1.11.31 Production Example — Percentage Validation

A production percentage validator should reject values that are structurally numeric but semantically invalid.

```python
import math


def validate_percentage(value):
    if isinstance(value, bool):
        raise TypeError("percentage must be numeric, not bool")

    if not isinstance(value, (int, float)):
        raise TypeError("percentage must be int or float")

    if isinstance(value, float) and not math.isfinite(value):
        raise ValueError("percentage must be finite")

    if not 0 <= value <= 100:
        raise ValueError("percentage must be between 0 and 100")

    return value
```

Why reject `bool` explicitly?

```python
print(isinstance(True, int))
```

Output:

```text
True
```

Python's type relationship is correct, but an application percentage normally should not accept `True` as `1`.

This illustrates the difference between:

```text
language-level compatibility
            and
domain-level validity
```

## 1.11.32 Production Example — Retry Backoff

A simple capped exponential backoff calculation can use numeric operations directly:

```python
def backoff_seconds(
    attempt,
    *,
    base_seconds=1.0,
    maximum_seconds=30.0,
):
    if attempt < 0:
        raise ValueError("attempt must be non-negative")

    delay = base_seconds * (2 ** attempt)
    return min(delay, maximum_seconds)
```

Examples:

```python
for attempt in range(6):
    print(attempt, backoff_seconds(attempt))
```

Production retry systems usually need more than the formula:

```text
backoff
+
jitter
+
maximum attempts
+
overall deadline
+
cancellation
+
observability
+
idempotency awareness
```

Unbounded exponentiation should not be driven by arbitrary external attempt values.

## 1.11.33 Production Example — Capacity Calculations

Exact counts should normally remain integers:

```python
nodes = 6
shards_per_node = 120

total_shard_capacity = nodes * shards_per_node

print(total_shard_capacity)
```

Output:

```text
720
```

If a planning ratio is approximate:

```python
target_utilization = 0.70
usable_capacity = int(total_shard_capacity * target_utilization)
```

The model intentionally uses:

```text
exact count        → int
planning ratio     → float
derived whole-unit capacity → explicit conversion
```

The conversion policy should be chosen according to whether flooring, ceiling, or rounding is operationally correct.

## 1.11.34 Production Example — Financial Values

Avoid using binary floating point when exact decimal financial semantics are required:

```python
from decimal import Decimal

unit_price = Decimal("19.95")
quantity = 3

subtotal = unit_price * quantity

print(subtotal)
```

Output:

```text
59.85
```

Another design uses integer minor units:

```python
unit_price_cents = 1995
quantity = 3

subtotal_cents = unit_price_cents * quantity
```

Financial correctness also requires explicit rules for:

- currency;
- decimal scale;
- rounding;
- tax calculations;
- exchange rates;
- serialization;
- database representation.

Choosing `Decimal` is important, but it does not by itself define the business policy.

## 1.11.35 Production Example — Storage Units

Storage calculations must identify their units.

Decimal units:

```text
1 MB = 1,000,000 bytes
1 GB = 1,000,000,000 bytes
```

Binary units:

```text
1 MiB = 1,048,576 bytes
1 GiB = 1,073,741,824 bytes
```

Example:

```python
bytes_used = 10 * 1024 ** 3
gib_used = bytes_used / 1024 ** 3

print(gib_used)
```

Output:

```text
10.0
```

Avoid labels such as `"GB"` when the calculation actually uses GiB semantics.

Units are part of the data model.

## 1.11.36 Numeric Input from External Systems

External systems often provide numbers as text:

```python
raw_port = "5432"
raw_threshold = "0.85"
```

A robust boundary separates parsing from validation:

```python
port = int(raw_port)

if not 1 <= port <= 65535:
    raise ValueError("port out of range")
```

For a float:

```python
import math

threshold = float(raw_threshold)

if not math.isfinite(threshold):
    raise ValueError("threshold must be finite")

if not 0 <= threshold <= 1:
    raise ValueError("threshold must be between 0 and 1")
```

The same principle applies to:

- environment variables;
- command-line arguments;
- API payloads;
- configuration files;
- CSV data;
- database results;
- message queues.

## 1.11.37 Numeric Resource Risk

Numeric inputs can create resource problems even when they are syntactically valid.

Examples include:

```python
10 ** enormous_exponent
2 ** enormous_exponent
```

or calculations that create huge integers, sequences, timeouts, buffer sizes, or iteration counts.

Validate:

```text
magnitude
+
range
+
units
+
expected complexity
+
downstream allocation
```

Do not rely only on the numeric type to protect the system.

## 1.11.38 Common Numeric Mistakes

### Using `float` for exact decimal money

Use `Decimal` or an approved integer-minor-unit design.

### Comparing floats with exact equality when approximation is involved

Use a domain-appropriate tolerance such as `math.isclose()`.

### Treating `//` as truncation toward zero

It performs floor division.

### Assuming `int(float_value)` performs floor

It truncates toward zero.

### Ignoring division by zero

Validate or otherwise control divisors.

### Accepting NaN or infinity accidentally

Use `math.isfinite()` when the domain requires finite values.

### Treating successful parsing as validation

`int("-1")` succeeds even when negative values are forbidden.

### Ignoring units

`MB` and `MiB` are not the same.

### Using `round()` without a defined rounding policy

Especially dangerous in financial and regulated calculations.

### Accepting `bool` where a domain expects an integer

`bool` is a subclass of `int`, but application semantics may require rejection.

### Assuming arbitrary-precision integers have no cost

They still consume CPU and memory.

### Using unexplained numeric literals

Prefer named constants when the number has domain meaning.

## 1.11.39 Troubleshooting Numeric Problems

A systematic numeric investigation should answer the following questions.

### Step 1 — Inspect the Type

```python
print(type(value))
```

Determine whether the value is:

```text
int
float
Decimal
complex
bool
str
another numeric type
```

### Step 2 — Inspect the Representation

```python
print(repr(value))
```

For floats, also inspect higher precision when useful:

```python
print(format(value, ".17g"))
```

### Step 3 — Identify the Required Semantics

Ask whether the quantity is:

```text
exact integer
approximate measurement
exact decimal
ratio
percentage
money
duration
byte count
identifier
```

### Step 4 — Check Finiteness

```python
import math

if isinstance(value, float):
    print(math.isfinite(value))
```

### Step 5 — Check Range

```python
if not 0 <= percentage <= 100:
    ...
```

### Step 6 — Check Units

Confirm whether values are expressed in:

```text
seconds or milliseconds
bytes or MiB
fraction or percentage
dollars or cents
```

### Step 7 — Check Conversion Behavior

Look for:

```python
int(...)
float(...)
round(...)
math.floor(...)
math.ceil(...)
```

and verify that the chosen conversion matches the intended policy.

### Step 8 — Check Floating-Point Assumptions

Inspect:

- exact equality;
- accumulated summation error;
- decimal-to-binary conversion;
- tolerance choices.

### Step 9 — Check Boundary Data

Trace where the value entered:

```text
environment
API
database
file
message
CLI
```

and whether parsing and domain validation both occurred.

### Step 10 — Check Resource Bounds

Determine whether magnitude, exponent, count, timeout, or allocation size can be controlled by an external source.

---

## 1.11.40 Production Engineering Rules

1. Choose numeric types according to the semantics of the quantity.
2. Use `int` for exact integral quantities.
3. Remember that Python integers are arbitrary precision but not free of CPU or memory cost.
4. Bound user-controlled magnitudes and exponents.
5. Use `float` when binary floating-point approximation is appropriate.
6. Do not expect every decimal fraction to have an exact binary floating-point representation.
7. Use `math.isclose()` or another domain-defined tolerance when approximate equality is intended.
8. Use `Decimal` or integer minor units when exact decimal semantics are required.
9. Construct `Decimal` from decimal strings when preserving the original decimal value matters.
10. Treat `/` as true division and `//` as floor division.
11. Remember that floor division is not truncation toward zero.
12. Validate or otherwise control divisors when zero is possible.
13. Use `int()` knowing that float-to-int conversion truncates toward zero.
14. Define rounding policy explicitly when correctness depends on it.
15. Use `math.isfinite()` when NaN and infinity are invalid domain values.
16. Do not use equality to detect NaN.
17. Separate parsing from domain validation.
18. Reject `bool` explicitly when a numeric domain should not accept Boolean values.
19. Keep units explicit in names, interfaces, documentation, and calculations.
20. Use dedicated representations for domain-sensitive quantities such as money.
21. Measure numeric performance problems before optimizing, but enforce resource limits before accepting untrusted numeric workloads.

def validate_percentage(value):

    return min(
        base_seconds * (2 ** attempt),

    )

## 1.11.45 Key Takeaways

Python's numeric system is powerful because it supports several different models:

```text
int
    exact integral arithmetic

float
    efficient approximate binary real arithmetic

Decimal
    explicit decimal arithmetic

complex
    complex-number arithmetic
```

The important engineering question is not:

```text
Can Python store this number?
```

It is:

```text
What quantity does this value represent,
what precision does it require,
what ranges and units are valid,
and what failure behavior is acceptable?
```

At production boundaries:

```text
external representation
        │
        ▼
      parse
        │
        ▼
numeric representation
        │
        ├── validate type semantics
        ├── reject invalid bool usage
        ├── check finiteness
        ├── check range
        ├── check units
        ├── apply rounding policy
        └── enforce resource limits
        │
        ▼
domain-valid value
```

The production model is:

```text
numeric correctness
       =
representation
       +
precision
       +
rounding
       +
range
       +
finiteness
       +
units
       +
validation
       +
resource limits
```

The central principle remains:

> **Numeric correctness requires choosing the representation that matches the quantity being modeled and enforcing that quantity's domain rules at system boundaries.**
